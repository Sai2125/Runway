# Runway — project brief for Claude Code

> Working name: **Runway**. A second brain that knows what time it is.
> Built at ADHD Hacks (Claude Code Community, Bangalore) in one day by a team of 2–3 ADHD builders.
> Read this whole file before writing code. When in doubt, the **Principles** section wins over convenience.

---

## 0. The one-liner

A friend in your browser (later: WhatsApp/Telegram/Notes) that remembers what you said you'd do, hides it until it matters, brings back **one** thing with runway to act, follows up like a friend, and — when you slip — drafts the reschedule message so slipping stops being a crisis.

**Tagline:** *Every other tool helps you not forget. Ours assumes you will — and makes it not matter.*

---

## 1. Problem

ADHD is not a memory problem. It is a **now / not-now** problem (Barkley): anything not in the present moment effectively doesn't exist. We *know* about the birthday, the deadline, "I'll send Rahul the deck tonight" — it just isn't in working memory at the moment it becomes actionable. Existing tools fail in four predictable ways:

1. **Remind on the day** → zero prep runway.
2. **Show everything** → backlog wall → app abandoned in 3 weeks.
3. **Trust our estimates** → which are systematically optimistic.
4. **Go red when we miss** → shame spiral → delete app.

They treat ADHD traits as bugs. **We treat them as the spec.**

---

## 2. Principles (non-negotiable design rules)

| # | Principle | ADHD basis | Implementation rule |
|---|---|---|---|
| P1 | **Hide everything not-now.** | now/not-now | There is no list view and no list endpoint. `/now` returns **one** item or an empty state. No badge counts anywhere. |
| P2 | **Time Optimism Index.** | time blindness | Every commitment stores `est_minutes`; completion stores `actual_minutes`. `optimism_index = median(actual/est)`; seeded 1.0 (demo: seed history so it reads ~2.4). Planner uses `est × index`, never raw `est`. |
| P3 | **Graceful failure.** | shame spiral | There is **no `overdue` state**. When `due` passes undone → state `slipped` → Claude drafts a reschedule/apology message → Send / Edit / Skip. Never the word "overdue", never red. |
| P4 | **Environmental triggers.** | implementation intentions | Nudge payload can carry an `atmosphere` (playlist link / mood cue). Sprint 2+. Engine must have the hook from day one. |
| P5 | **The bot is the nudger.** | externalised executive function | After a surface, if no reply in 30 min → one check-in; then back off. Honors "not today" / "give me 20" literally. |
| P6 | **A friend, not a system.** | rigid systems get abandoned | Every outbound line is generated by Claude with the friend prompt. Nothing templated. Banned words: *overdue, productivity, should have, failed*. |
| P7 | **Zero setup, non-techie.** | — | Open the page, talk. Text, mic (Web Speech API), or paste/drop a photo of handwriting. No accounts in v1. |
| P8 | **First step, always.** | initiation cost | Every surfaced item carries `first_step`: the smallest concrete move ("open the deck and look at the last slide"). |
| P9 | **App-agnostic.** | — | Channels are doors; the brain is one thing. Keep channel code in `adapters/`, never in core. Web + Telegram today (parallel tracks); WhatsApp/Notes next. Adapters may import only what `CORE_CONTRACT.md` lists. |

## 3. Architecture (phase 1 — one brain, two doors)

Two channels are being built **in parallel** today by different people. Both are thin adapters over the
same core. The core never knows which door a commitment came through or which door a nudge leaves by.

```
 DOOR 1 — Browser (owner: backend/frontend team)          DOOR 2 — Telegram (owner: Telegram track)
 ├─ Dump bar: text · mic (webkitSpeechRecognition)         ├─ text message
 │            · paste/drop image                            ├─ voice note (.ogg) → Groq Whisper → text
 ├─ Now view: one card or "Nothing needs you right now."   ├─ photo → Claude vision → text
 ├─ Horizon strip: hazy, pull-up, scroll-toward            ├─ /now → one card + inline buttons
 ├─ Slip sheet: draft + Send / Edit / Skip                 ├─ inline buttons: Doing it · Give me 20 · Not today
 └─ Index tile: live multiplier                            │                  Send it · Skip
          │ fetch + SSE (/events)                          └─ nudges pushed by the engine (long polling, no webhook)
          ▼                                                          │ backend/adapters/telegram.py
 ┌────────────────────────────────────────────────────────────────────┘
 ▼
 CORE  (backend/core.py — contract in backend/adapters/CORE_CONTRACT.md)
 ├─ dump(user_id, text, source) / dump_image(...)   → Claude extraction → commitments (state=hidden) → voice `ack`
 ├─ now(user_id)                                    → single soonest `now` item, rendered by voice `surface`
 ├─ act(id, action)  /  slip_send(id)  /  slip_skip(id)
 ├─ link_channel(user_id, channel, chat_id) / chat_id_for(...)   ← routing for outbound
 ├─ register_outbound(handler)  → OUTBOUND_HANDLERS               ← every adapter registers once
 ├─ horizon loop (APScheduler 60s, §5) → emits {mode, commitment_id, text, draft?} to SSE AND every outbound handler
 └─ voice layer: Claude friend prompt writes every outbound line; adapters only format + send
          │
 FastAPI wraps core for the browser:
   POST /dump · GET /now · POST /act · POST /slip/send · GET /events (SSE) · GET /debug/advance?minutes=N
          │
 SQLite (runway.db)
 ├─ commitments(id, user_id, what, due, due_fuzziness, people[], type, est_minutes, first_step, state, surfaced_at, created_at, source)
 ├─ events(id, commitment_id, est_minutes, actual_minutes, completed_at)
 ├─ channels(user_id, channel, chat_id)   ← NEW: routes nudges to telegram/web/whatsapp
 └─ prefs(key, value)  — optimism_index, quiet_hours, name
```

**State machine:** `hidden → now → done` · `now → slipped → closed`. Nothing else. No `overdue`.

**Identity today:** `user_id` is a string — `tg:<telegram_user_id>` for Telegram, `web:demo` for the browser.
To demo "dump on the web → nudge on Telegram", seed `link_channel("web:demo", "telegram", <chat_id>)` once.

**Until the real core lands:** `backend/core_fake.py` implements the contract in-memory (with its own 10s
horizon tick and `advance(minutes)` for demos). The Telegram adapter imports it today; switching to the real
core is a one-line import change. The backend team's integration checklist is the three items at the end of
`CORE_CONTRACT.md`: implement the functions, add the `channels` table, loop over `OUTBOUND_HANDLERS` in `horizon.py`.

## 4. Tech stack & why

| Layer | Choice | Why for a one-day build |
|---|---|---|
| Backend | FastAPI + uvicorn | Async, SSE-friendly, tiny |
| LLM | Anthropic SDK — Claude Sonnet (extraction, voice), vision for handwriting photos | One model, structured output + tone |
| STT (web) | Browser `webkitSpeechRecognition` (Chrome) | Free, zero API; no server audio handling |
| STT (Telegram) | Groq Whisper API `whisper-large-v3-turbo` (`backend/stt.py`) | Voice notes arrive as `.ogg` server-side; Claude doesn't take audio; Groq is free-tier and ~1s |
| Telegram | `python-telegram-bot` v21, long polling | Free, 5-min BotFather setup, no public URL needed |
| Storage | SQLite via `sqlite3` or SQLModel | One file, inspectable live in the demo |
| Scheduler | APScheduler `BackgroundScheduler` | No cron, no queue |
| Frontend | Vanilla HTML/CSS/JS (fastest) or Vite+React | Chat is the product; keep it light |
| Push | Server-Sent Events | Simpler than websockets, enough for one user |
| Env | `uv` + `.env` (`ANTHROPIC_API_KEY`) | Everyone runs it on a laptop |

## 5. Horizon engine (the heart)

Runs every 60 s. For each `hidden` commitment:

```
lead_time(type):  birthday 5d · deadline 3d · event 2d · errand 1d · promise 0
surface_at = due − lead_time(type) − (est_minutes × optimism_index)
if now >= surface_at  → state = now, surfaced_at = now, emit SSE surface, send voice nudge
```
For each `now` commitment:
```
if now > due and state != done → state = slipped, emit SSE slip, generate apology draft
if surfaced_at + 30min passed with no /act → one check-in via voice layer, then silence
```
Quiet hours (prefs) suppress nudges but not state changes.

`/now` picks the `now` item with the earliest `due`. Ties → most recently surfaced.

## 6. Extraction — `prompts/extract.md`

```
You extract commitments from messy human input for someone with ADHD. Input may be typed text, a speech transcript, or a transcription of a handwritten note. One input may contain several commitments. Today is {{now_iso}} in Asia/Kolkata.

Return ONLY a JSON array. Each item:
{
  "what": "<short imperative, e.g. 'send Rahul the deck'>",
  "due": "<ISO 8601 with offset, your best resolution of fuzzy time>",
  "due_fuzziness": "<the user's own words: 'tonight', 'the 20th', 'friday', or null>",
  "people": ["<names mentioned>"],
  "type": "promise | deadline | birthday | event | errand",
  "est_minutes": <integer; infer sensibly if absent>,
  "first_step": "<the smallest concrete physical move to begin, under 12 words>"
}

Rules: 'tonight' = 23:00 today. 'this week' = Friday 17:00. Birthdays with no year = next occurrence. If no date at all, set due to null and type to errand. Never invent people. Never add commentary.
```
Vision variant: prepend *"The image is a photo of a handwritten or printed note. Transcribe it faithfully first, then extract."*

## 7. Friend voice — `prompts/friend.md`

```
You are Runway, a close friend who happens to have a perfect memory and an honest sense of time. You are talking to someone with ADHD. You are never a productivity system.

Voice: warm, brief, slightly nosy, dry humour allowed. 1–3 sentences. Name time honestly ("it's 9:40, tonight is getting thin") without moralising. Never use the words: overdue, productivity, should have, failed, procrastinate. Never say "just" before a task.

You will be given a MODE and CONTEXT (the commitment as JSON, the current time, the user's optimism index, recent history).

MODE = surface   → Bring the item back. Include the honest duration ("you said 30; you usually take ~75 on these") and the first_step verbatim or lightly rephrased. End with an implicit choice, not a command.
MODE = checkin   → One gentle nudge referencing what they said and when ("you told Rahul 'tonight' at 4:12"). Offer to hold the fort. Do not repeat the first step.
MODE = slip      → Acknowledge lightly ("that one got away — happens"). Then write a ready-to-send message TO the other person in the user's voice: honest, short, gives a new concrete time, no grovelling. Return JSON: {"line": "<what you say to the user>", "draft": "<message to the other person>", "new_due": "<ISO>"}.
MODE = ack       → After a dump: confirm what you understood in one line and release them ("Got both. Go do your thing."). Never list more than 3 items; summarise beyond that.
MODE = backoff   → They said not today / give me 20. Respect it in one short line. No guilt.
MODE = index     → Explain their multiplier like a friend showing them a stat about themselves. Curious, not corrective.
```

## 8. Interface spec — five surfaces, no lists

1. **Dump bar** — bottom, always present. One input. Mic button → Web Speech live transcript fills the field → Enter sends. Paste/drop image → Claude vision. On success the bot replies with `ack` in one line and the items *visibly sink* below the horizon line (CSS animation).
2. **Now view** — the whole screen. One card: `what` · `people` · honest time ("you said 30 · history says 75") · **first step** · actions: *Doing it* / *Give me 20* / *Not today*. Empty state: "Nothing needs you right now." No counts, no lists, no red.
3. **Horizon strip** — a hazy band peeking from the bottom; pull up to scroll *toward* the horizon. Items blur with distance and sharpen as they approach. Deliberately not scannable — it is a horizon, not a list. (UX reference: spatial, scroll-driven, SOOT-Spiral-flavoured.)
4. **Slip sheet** — slides up on slip. The friend's line + the draft in a quoted block + *Send / Edit / Skip*. Send → `/slip/send` → closed, re-filed with `est × index`.
5. **Index tile** — small, top corner. Live multiplier ("2.4×"). Tap → said-vs-actual bars.

**Visual language** (shared with the landing page): dusk-to-dawn palette — ink `#0d0b14`, fog `#241d3a`, cream `#f4efe6`, ember `#ff8a5b`, dawn `#ffd9a8`, sage `#9fd3b6`. Fonts: Instrument Serif (display), DM Sans (body), JetBrains Mono (numbers). Things below the horizon are foggy/blurred; the one that has crossed glows.

## 12. Demo script (3 minutes)

1. **Open on the landing page hero** (10 s). Read the tagline aloud.
2. **Open on us:** show Runway having nudged the team about *this* demo slot 20 minutes ago. (20 s)
3. **Dump:** speak a voice note into the dump bar + paste a photo of a scribbled note. Ack. Items sink. Screen shows nothing. (40 s)
4. **Surface:** fast-forward the clock (`/debug/advance?minutes=…`). One card appears with honest time and a first step. (30 s)
5. **Slip:** advance past due. No red. Slip sheet with the drafted message. Tap Send. Loop closed. (40 s)
6. **Index:** tap the tile — "2.4×". (15 s)
7. Close on the orbit: "Web today. WhatsApp, Telegram, Notes next. One brain, many doors." (15 s)

Include a `/debug/advance` endpoint that shifts the engine's notion of "now" — the demo depends on it.

## 13. Coding conventions for Claude Code

- Python 3.11, type hints, `uv` for deps, `ruff` clean. Keep files small; one concern per module.
- All Claude calls go through `extract.py` or `voice.py` — never inline prompts elsewhere. Prompts live in `prompts/*.md` and are loaded at runtime.
- Never add a list endpoint, a badge count, or an `overdue` state, even "for debugging". Use SQLite directly if you need to inspect.
- Every outbound user-facing string comes from the voice layer. If you find yourself writing UI copy for the bot, stop and route it through `voice.py`.
- Channel-specific code lives in `adapters/`. Core never imports an adapter.
- Fail soft: if Claude errors, ack with a fixed fallback line and log; never surface a stack trace to the user.
- Commit small and often with messages that name the principle served (e.g. `feat(horizon): surface_at uses optimism_index (P2)`).
