# Core ↔ Adapter contract (what the Telegram adapter needs from the backend)

> **Status:** implemented in `backend/core.py` (SQLite). Doors may run as separate processes; outbound
> nudges are written to the `outbox` table per channel — poll `core.outbox_pull(channel)` and ack with
> `core.outbox_ack(ids)`. `now()` is exposed as `core.now_card()` (name clash with time). `slip_send()`
> returns a dict `{line, draft, recipient_chat_id, people}` so the door can deliver the draft.
> Extra helpers: `link_alias`, `register_contact`, `contact_chat`, `set_actual`, `advance`, `reset_clock`, `snapshot`.

Hand this to whoever owns `backend/core.py`. The Telegram adapter (and later WhatsApp, Notes, etc.)
imports **only** these names from `backend.core`. Core never imports an adapter.

Until the real core exists, `backend/core_fake.py` implements this exact contract in-memory,
so the adapter can be built and demoed independently. Swap by changing one import line.

## Functions (all `async`)

| Signature | Returns | Notes |
|---|---|---|
| `link_channel(user_id: str, channel: str, chat_id: str) -> None` | — | Stores routing for outbound nudges. `channel` = "telegram" for now. Upsert. |
| `chat_id_for(user_id: str, channel: str) -> str \| None` | chat id or None | Reverse lookup used by outbound. |
| `hello(user_id: str) -> str` | one line | Voice layer, mode `ack`, first contact. |
| `dump(user_id: str, text: str, source: str) -> str` | one-line ack | Runs extraction → stores commitments as `hidden` → returns voice-layer `ack`. `source` ∈ web, telegram, telegram-voice, telegram-photo. |
| `dump_image(user_id: str, image: bytes, source: str) -> str` | one-line ack | Claude vision transcribe → same as `dump`. |
| `now(user_id: str) -> dict \| None` | `{id, text}` or None | The single soonest `now` item, already rendered by the voice layer (mode `surface`). None → adapter shows "Nothing needs you right now." |
| `act(commitment_id: str, action: str, actual_minutes: int \| None = None) -> str` | one line | `action` ∈ doing, snooze20, not_today, done. Returns voice-layer line (`backoff` or `ack`). |
| `slip_send(commitment_id: str) -> str` | one line | Marks closed, re-files with learned duration. Returns confirmation line. |
| `slip_skip(commitment_id: str) -> str` | one line | Closes without sending. |
| `register_outbound(handler: Callable[[str, dict], Awaitable[None]]) -> None` | — | Adapter registers once at startup. Core calls **every** registered handler when the horizon engine emits. |

## Outbound event shape (core → adapter)

```python
await handler(user_id, {
    "mode": "surface" | "checkin" | "slip" | "index",
    "commitment_id": "c_123",
    "text": "<already generated by the voice layer>",
    # slip only:
    "draft": "<message to the other person>",
    "people": ["Rahul"],
})
```

The adapter never writes copy. It only formats, attaches buttons, and sends.

## Storage the backend must add

```sql
CREATE TABLE IF NOT EXISTS channels (
  user_id TEXT NOT NULL,
  channel TEXT NOT NULL,          -- 'telegram' | 'web' | 'whatsapp'
  chat_id TEXT NOT NULL,
  PRIMARY KEY (user_id, channel)
);
```

## One line in horizon.py

Wherever the engine currently emits SSE for the web, also:

```python
for h in core.OUTBOUND_HANDLERS:
    await h(user_id, event)
```

## Identity (keep it simple today)

`user_id` is a string. For Telegram, use `f"tg:{telegram_user_id}"`. For the web, whatever the frontend
already uses (e.g. "web:demo"). If the demo needs "dump on web → nudge on Telegram", call
`link_channel("web:demo", "telegram", <your chat id>)` once at seed time so both doors map to one brain.
